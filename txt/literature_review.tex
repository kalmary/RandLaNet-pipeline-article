\section{Literature Review}

\subsection{Point Cloud Semantic Segmentation}

Point cloud semantic segmentation assigns a~semantic class to each measured point. Point clouds are unordered and irregularly distributed~\citep{pointnet,pointconv}, and outdoor LiDAR scans exhibit non-uniform sampling density, particularly across different distances from the sensor~\citep{cylinder3d}. A~single LiDAR frame may also contain incomplete observations of occluded objects~\citep{svqnet}. Distinguishing semantic classes can require both fine local geometry and broader spatial context~\citep{pointnetpp,spg}.

Segmentation methods can be grouped by their primary working representation. Point-based architectures, including PointNet, PointNet++, and RandLA-Net, operate directly on point sets~\citep{pointnet,pointnetpp,randlanet}. Voxel-based methods discretize three-dimensional space; SSCN and Minkowski networks process the resulting sparse representations~\citep{sscn,minkowski}. Projection-based approaches map LiDAR measurements to structured two-dimensional representations, as in RangeNet++ and PolarNet~\citep{rangenet,polarnet}. Graph-based methods such as Superpoint Graph encode relations between geometric regions~\citep{spg}, whereas hybrid architectures such as PVCNN combine point and voxel representations~\citep{pvcnn}. These groups are not necessarily mutually exclusive because an architecture may use more than one representation.

Within this hierarchy, the present study focuses on the point-based RandLA-Net architecture, which was designed for efficient semantic segmentation of large-scale point clouds~\citep{randlanet}.

\subsection{Large-Scene Processing}

Large benchmark scenes may contain tens or hundreds of millions of measured points, as illustrated by Semantic3D, DALES, and Toronto3D~\citep{semantic3d,dales,toronto3d}. Such scenes commonly exceed the practical input size used by large-cloud segmentation models~\citep{randlanet,sensaturban}. Because the complete cloud cannot be passed through the model at once, the processing workflow constructs bounded fragments or queries at selected scene locations. At a~fixed point density and with the same representation, reducing a~fragment's spatial extent reduces its memory demand, but may divide objects and remove useful context. Larger fragments retain more context but can exceed the available memory.

Partitioning also introduces boundaries into a~continuous scene, so objects that cross them may be observed only partially. If the union of the processed fragments does not cover the scene, some points receive no direct prediction. Overlapping fragments or repeated queries can provide more than one prediction for other points, requiring a~selection or fusion rule. Predictions made on reduced or transformed inputs must finally be reconstructed at the resolution of the measured cloud. Complete-scene cost includes data preparation, spatial indexing, ensuring complete coverage, all inference passes, and any fusion and reconstruction. Model throughput describes only one stage of this process.

Density variation changes the physical area represented by a~model input. At a~given local density, a~fixed-cardinality sample has a~stable tensor size; across regions with different densities, the same cardinality spans more area where points are sparse. A~fixed-extent fragment maintains constant metric support, while its point count varies; reduction or padding is needed when the model interface requires a~fixed cardinality. SensatUrban refers to these alternatives as constant-number and constant-volume input sets, respectively~\citep{sensaturban}. On that dataset, the PointNet and RandLA-Net baselines report different accuracy values under the tested downsampling and input-set construction settings~\citep{sensaturban}.

Variation in density is one component of domain shift rather than a~complete description of it. LiDomAug aggregates motion-compensated frames into a~dense world model~\citep{lidomaug}. Selected cylindrical LiDAR configurations are rendered to a~range map with visibility and motion distortion and then back-projected to a~point cloud~\citep{lidomaug}. The configurations vary angular resolution, field of view, and mounting pose; samples are generated on demand during training, and the method is reported not to require target-domain data~\citep{lidomaug}.

In Complete \& Label, a~sparse voxel completion network maps an input scan to a~completed voxel surface, and segmentation is performed in this canonical domain~\citep{complete-label}. Source labels are propagated to the completed surface during training; at inference, predicted surface labels are projected back to the target points~\citep{complete-label}. In the SynLiDAR-to-SemanticPOSS setting, DGT reduces the 64-beam source pattern toward the 40-beam target pattern, then removes source points according to source--target point-count ratios computed for distance intervals~\citep{densityshift}. The planned voxel-grid experiments in this study examine controlled density reduction; they do not reproduce every variation between acquisition domains.

\subsection{Architectures for Large-Scale Point Cloud Segmentation}

Point-based architectures operate directly on the input points and their coordinates. PointNet applies a~shared multilayer perceptron (MLP) to each point and uses symmetric max pooling to obtain an order-invariant global descriptor~\citep{pointnet}. For segmentation, this descriptor is copied to every point and concatenated with an earlier per-point feature; further shared layers produce the point-wise class scores~\citep{pointnet}.

PointNet++ organizes this operation spatially. Each set-abstraction layer selects centroids with FPS, retrieves neighbors by ball query, and applies PointNet to each local set; repeating these layers yields features over progressively broader contextual scales~\citep{pointnetpp}. PointConv estimates local sampling density with kernel density estimation and passes the inverse density through a~learned nonlinear transformation~\citep{pointconv}. An MLP of relative coordinates supplies the spatial weight function for the convolution~\citep{pointconv}.

Point Transformer applies vector self-attention within k-NN neighborhoods and encodes relative point positions in the attention operation~\citep{pointtransformer}. Its transition-down modules use FPS and k-NN pooling to construct a~hierarchical point representation with fewer points at successive stages~\citep{pointtransformer}. KPConv associates each kernel point with a~learned weight matrix~\citep{kpconv}. For each neighbor, every matrix is scaled by a~linear influence that decreases with the distance between the neighbor's relative position and the kernel point~\citep{kpconv}. Radius queries collect all points within the support, so neighborhood cardinality varies with local sampling; regular grid subsampling sets the point spacing between layers~\citep{kpconv}.

PVCNN quantizes point features onto a~low-resolution voxel grid, applies convolutions over voxel neighborhoods, and maps the resulting features back to points through trilinear interpolation~\citep{pvcnn}. A~parallel branch applies a~shared transformation to the individual points, retaining fine point-based features before the point and voxel outputs are added~\citep{pvcnn}.

The Superpoint Graph workflow first partitions geometrically homogeneous points into superpoints, which become the graph nodes and determine its granularity~\citep{spg}. SPG inherits connectivity from a~point-level Voronoi adjacency graph: two superpoints are connected if at least one Voronoi-adjacent point pair links them. Edge-conditioned convolution then passes messages whose weights depend on the superedge attributes~\citep{spg}. The paper states that the number of superpoints is typically several orders of magnitude smaller than the number of input points~\citep{spg}.

Voxel quantization maps measurements in the same cell to a~shared coordinate and determines the number of distinct occupied coordinates~\citep{minkowski}. SSCN and Minkowski networks operate on these active sites rather than a~dense lattice~\citep{sscn,minkowski}. Cylinder3D transforms the cloud to cylindrical coordinates, producing cells whose Cartesian footprint increases with range. On the SemanticKITTI training set, the paper reports a~more balanced proportion of non-empty cells across distance intervals than with cubic Cartesian partitioning, especially at long range~\citep{cylinder3d}. Its asymmetrical residual blocks strengthen horizontal and vertical three-dimensional kernels for driving geometry~\citep{cylinder3d}.

RangeNet++ applies a~two-dimensional fully convolutional network to a~spherical range image and later transfers the predicted labels back to the scan~\citep{rangenet}. PolarNet divides the bird's-eye view into bins of polar radius and azimuth; the azimuth bins widen metrically with range~\citep{polarnet}. A~small PointNet followed by max pooling encodes the points in each cell, and a~two-dimensional CNN processes the resulting grid features~\citep{polarnet}. On the SemanticKITTI validation set, both polar and Cartesian grids contain a~mean of 0.7 points per cell, but the reported standard deviation is 1.4 for the polar grid and 3.2 for the Cartesian grid~\citep{polarnet}.

RandLA-Net was introduced as an efficient, lightweight architecture for directly inferring per-point semantics in large-scale point clouds~\citep{randlanet}. Its authors report processing 1~million points in a~single pass~\citep{randlanet}. RandLA-Net is held fixed in this study; only the external workflows used to prepare its inputs and reconstruct its outputs are compared.

\subsection{Large-Scene Processing Pipelines}

A~processing pipeline can separate scene-level downsampling from the construction of bounded model inputs. SensatUrban separates initial downsampling (grid or random) from input-set construction (constant number or constant volume)~\citep{sensaturban}.

Spatial-grid workflows construct inputs through quantization, which maps points in the same spatial cell to single grid coordinate~\citep{minkowski}. SSCN and Minkowski networks then store and process features only at occupied grid cells~\citep{sscn,minkowski}.

RangeNet++ converts each rotating LiDAR scan into a~spherical range image and stores the image coordinates $(u,v)$ of its measured points. After inference, the predicted label image assigns a~discrete label to each point through these stored coordinates. A~subsequent range-aware k-NN consensus refines the transferred labels to reduce discretization, label-bleeding, and shadow artifacts~\citep{rangenet}.

For point-based inputs, random or grid reduction can decrease the number of points before samples are constructed~\citep{sensaturban}. FPS selects spatially distant points and produces a~more dispersed sample~\citep{pointnetpp,randlanet}. In the official RandLA-Net generator, query scheduling chooses later centers from possibility values updated after earlier queries~\citep{randla-dataset}. Non-overlapping fragments provide at most one fragment-level observation for each covered point. Overlap and coverage-driven sampling can create repeated observations and require more inference passes. When a~point receives multiple predictions, a~pipeline can select one, vote over discrete labels, or fuse class probabilities before the final class decision.

Reconstruction may use correspondences stored during preprocessing. Alternatively, reconstruction-time spatial queries can transfer values from one or more nearby prediction anchors to each target point.

The official RandLA-Net Semantic3D workflow begins by grid-subsampling each cloud at 0.06~m and dividing RGB values by 255~\citep{randla-preprocess}. It builds a~KDTree over the reduced points and, for test clouds, stores the indices of the nearest reduced points for later reprojection~\citep{randla-preprocess}. The input generator retrieves 65,536 points per query with k-NN rather than using windows of fixed spatial extent~\citep{randla-config,randla-dataset}.

During testing, the generator maintains a~possibility value for every reduced point. It selects the cloud with the lowest minimum possibility, locates the least-covered point in that cloud, and perturbs this point to obtain the next query center~\citep{randla-dataset}. After the k-NN query, the selected points are recentered in XY. Their possibility values increase by $(1-r_i^2/r_{\max}^2)^2$, where $r_i=\lVert\mathbf{x}_i-\mathbf{c}\rVert_2$ is the three-dimensional distance from point $i$ to the perturbed center and $r_{\max}$ is the maximum such distance in the query. Points near the center receive the largest increment, reducing their priority as subsequent query centers~\citep{randla-dataset}. The generator uses the updated possibility values to choose later centers; these values are unrelated to FPS distances or the network's internal random sampling.

The tester stores class-probability buffers on the reduced clouds. Predictions from successive queries update these buffers by exponential smoothing: 0.98 of the stored value and 0.02 of the new value~\citep{randla-tester}. When the finite test iterator is exhausted, the tester computes the global minimum possibility. Reprojection is triggered if this minimum exceeds the preceding checkpoint by more than four~\citep{randla-tester}. The stored indices select the reduced-cloud probabilities for the original test points, and \texttt{argmax} is applied afterward~\citep{randla-preprocess,randla-tester}. The nearest-neighbor query that produced these indices ran during preprocessing; inference uses array indexing rather than a~separate 1-NN procedure~\citep{randla-preprocess,randla-tester}. This official Semantic3D workflow serves as the reference pipeline in the present study.
